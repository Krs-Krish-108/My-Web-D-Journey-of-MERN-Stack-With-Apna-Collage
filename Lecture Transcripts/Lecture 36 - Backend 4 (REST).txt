# Building RESTful API with Express

## Summary
### Flow Summary
Speaker 1 ne RESTful APIs chapter shuru kiya: REST aur CRUD concepts samjhaye, Quora jaisa posts page banane ke routes plan kiye, aur Express server ka basic setup kiya.

### Chapter ka project
- Quora/Twitter jaisa posts page banega ("ACORA post" suna gaya, shayad Quora post); har post mein username aur content
    - Features: saare posts dekhna, individual post detail, naya post, edit, delete
- UI par focus nahi; chapter ke baad cards ya better styling khud add kar sakte hain
- Yahi concept blog, Twitter replica ya Instagram page (photo option ke saath) mein use ho sakta hai

### REST aur CRUD concepts
- REST = Representational State Transfer: web services banane ke rules (constraints), koi package ya technology nahi
- RESTful APIs woh hain jo REST rules follow karti hain, JavaScript naming conventions jaisa tareeka
- CRUD: Create, Read, Update, Delete; har operation ke liye alag API endpoint
- Resource woh data hai jis par CRUD hota hai; is project mein resource posts hain

### REST best practices aur HTTP verbs
- Twitter API example: /users, /users/id, /tweets, /tweets/id; path mein sirf resource ka naam
- Endpoint paths mein nouns use karo, verbs nahi: /deleteUsers nahi, /users par DELETE request
- Blog post "Practices for REST API Design" chapter ke baad padhne ki salah
- GET read, POST naya data, PUT poora update, PATCH partial update, DELETE remove

### Planned routes
- GET /posts: index route, saare posts; POST /posts: create route, naya post
- GET /posts/id: view route, ek post detail; id abhi server par khud generate hogi
- PATCH /posts/id: update route, sirf content badlega (PUT bhi same tarike se likh sakte hain)
- DELETE /posts/id: destroy route, REST convention ke hisaab se naam

### Express project setup
- "REST class" folder mein npm init, express aur ejs install, index.js banaya, port 8080
- views (EJS templates) aur public (CSS) folders; view engine ejs aur express.static set kiya
- Form data parse karne ke liye express.urlencoded with extended: true middleware
- GET / par "server working well" response se setup test kiya; ab pehli API banana baaki

# Creating Posts API with EJS

## Summary
### Flow Summary
Speaker 1 walked through building a Quora-style posts app in Express and EJS: index, new/create, and show routes, redirect, and UUID-based ids, then began the PATCH update route.

### Index Route: GET /posts
- Posts stored in a `let` array (not const) so they can be deleted later; each post has username and content.
- Route named /posts after the resource noun, not a verb like /viewposts, as a valid RESTful convention.
- index.ejs renders 'Quora posts' (heard as 'kora posts') by looping posts with EJS tags, showing @username in H3 and content in H4.
- Styling in public/style.css: maroon H1, light background for .post, italic .user; fixed by linking the stylesheet and using app.use, not app.set.

### Create Route: GET /posts/new and POST /posts
- Two-step flow: GET /posts/new renders new.ejs form, which submits a POST to /posts to add the post.
- Form uses input name 'username' and textarea name 'content', matching names read from request.body in the backend.
- Without method/action the form sent a GET with query string data; setting method POST and action /posts fixed it.
- After pushing the new post, res.redirect('/posts') returns to the list (default status 302); index page links to 'Create new post'.

### Show Route: GET /posts/:id
- Each post gets a unique id; route reads request.params id and uses posts.find to locate the post.
- show.ejs renders 'Here is your post in detail' with id, username, content, reusing post/user classes and stylesheet link.
- Invalid ids return undefined and error; an error template was skipped, assuming correct ids for now.
- 'See in detail' links on each post initially broke because the href included a colon before the id.

### Unique IDs with UUID
- Counter-based incrementing ids rejected as too basic; uuid package (npm install uuid) used instead.
- v4 imported as uuidv4 and called for seed posts and for each new post in the POST route.

### Update Route: PATCH /posts/:id
- PATCH /posts/:id will update only a post's content; id and username stay unchanged. PUT would also work.
- Implementation with app.patch was just starting when the transcript ended.

# Implement Post Edit Feature

## Summary
### Flow Summary
Speaker 1 taught a Hinglish coding tutorial completing CRUD for a Quora-style posts app in Express: PATCH-based editing via an edit form with method-override, and a DELETE destroy route.

### PATCH Update Route
- Update route: PATCH on /posts/:id edits only a post's content; id and username stay unchanged
    - PUT could also be used, with almost the same syntax
- Tested via Hopscotch with form-urlencoded body (content param); id read from params, new content from req.body.content
- Internal server error occurred because IDs reset whenever the server restarts; fixed by fetching a fresh ID

### Edit Form Flow
- Added Edit link per post in index.ejs pointing to GET /posts/:id/edit, which renders edit.ejs
- edit.ejs shows post id and username (not editable) plus a textarea prefilled with content (10 rows, 35 columns)
- Content came through undefined until the textarea was given name="content"
- PATCH route now redirects to /posts after updating; redirect is near-instant

### method-override Package
- HTML forms only send GET or POST, so the npm method-override package is used to send PATCH, PUT, DELETE
- Uses query-value approach: form method POST, action ends with ?\_method=PATCH; backend uses app.use(methodOverride('\_method'))

### DELETE Destroy Route
- Delete button per post wrapped in a form posting to /posts/:id?\_method=DELETE, avoiding axios or fetch
- app.delete filters the posts array by id, then redirects to /posts
    - Error 'cannot access post before initialization' fixed by reassigning the existing posts variable
- Create, read, update, and delete now all work on the posts platform

### Homework
- Build your own RESTful CRUD app, e.g. Instagram (photo plus caption), Twitter, Threads, or a blog page
    - Create via POST, read via GET, update via PUT or PATCH, delete via DELETE

### Next Steps
- (Students) Build a RESTful CRUD app (Instagram, Twitter, Threads, or blog) as homework
