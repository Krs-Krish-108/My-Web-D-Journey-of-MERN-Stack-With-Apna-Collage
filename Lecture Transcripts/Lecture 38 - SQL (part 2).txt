# Understanding SQL WHERE Clause

## Summary
### Flow Summary
SQL clauses ka demo: WHERE, uske operators (arithmetic, comparison, logical, bitwise), LIMIT, ORDER BY aur aggregate functions (MAX, MIN, COUNT, AVG, SUM) ek Instagram-style user table par samjhaaye gaye.

### WHERE Clause
- Clauses conditions hoti hain jinse specific data milta hai; syntax: SELECT columns FROM table WHERE condition
- followers >= 200 se 3 users aaye (200, 300, 200 followers); sirf NAME, FOLLOWERS bhi select kar sakte hain
- AGE < 16 se 2 users aaye jinki age 14 aur 15 hai

### Operators ke Types
- Arithmetic: +, -, \*, /, modulo; WHERE age + 1 = 18 se Donald (age 17) mila
- Comparison: =, not equal, >, >=, <, <=; Logical: AND, OR, NOT, IN, BETWEEN
- Bitwise operators bits (0 aur 1) par kaam karte hain; computer data current hone ya na hone se 1/0 store karta hai
- Bitwise AND (&) sirf 1 & 1 par 1 deta hai; bitwise OR (|) koi ek value 1 ho to 1 deta hai

### Logical Operators Detail Mein
- AND: age > 15 aur followers > 200 se sirf Casey (age 16, 300 followers) aaya; OR se 2 users aaye
- BETWEEN 15 AND 17 se 3 users aaye, range ke andar wale values
- IN list se match karta hai: email list se Bob aur Donald mile; non-matching value par error nahi aata
- Do naye users (id 5, 6) insert kiye; age IN (14, 16) se 4 users, NOT IN se Bob aur Donald (15, 17)

### LIMIT aur ORDER BY
- LIMIT return hone wali rows par upper limit lagata hai, WHERE ke saath ya bina use ho sakta hai
- ORDER BY column se sorting: ASC (badhte kram) ya DESC (ghatte kram); kuch na likho to default ascending

### Aggregate Functions
- Set of values par calculation karke single value return karte hain: AVG, MAX, MIN, COUNT, SUM
- Results: MAX(followers) 10,000, MAX(age) 17, MIN(age) 14, AVG(age) 15.333, SUM(followers) 11,223
- COUNT(age) WHERE age = 14 ka result two aaya

# SQL GROUP BY and HAVING

## Summary
### Flow Summary
SQL lecture: GROUP BY aggregate functions ke saath, HAVING groups par condition, clauses ka order, aur UPDATE, DELETE, ALTER, TRUNCATE vs DROP examples ke saath samjhaye gaye.

### GROUP BY aur HAVING
- GROUP BY same value wali rows ko summary rows mein group karta hai, aksar aggregate function ke saath use hota hai
    - Example: SELECT age, count(id) FROM user GROUP BY age: 14 ke 2, 15 ka 1, 16 ke 2, 17 ka 1
    - max(followers) per age: 14 mein 400, 15 mein 200, 16 mein 10,000, 17 mein 200
- Jo column GROUP BY mein nahi hai (jaise name), use aggregate ke bahar select karne par error aata hai
- HAVING groups par condition lagata hai, WHERE rows par; HAVING ke liye pehle GROUP BY zaroori hai
    - HAVING max(followers) > 200 se sirf age 14 (400) aur 16 (10,000) groups aaye

### Clauses ka general order
- Order: SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY
- ORDER BY age DESC lagane par age 16 upar aur 14 neeche aa gaya

### UPDATE aur DELETE
- UPDATE user SET followers = 600 WHERE age = 16 se saare 16 saal wale users ke followers 600 ho gaye
- Pehli baar UPDATE par Error code 1175 (safe updates mode); fix: SET SQL\_SAFE\_UPDATES = 0
- DELETE FROM user WHERE age = 14 se 14 age wale users hata diye; WHERE bhoolne par saari rows delete hoti hain

### ALTER TABLE operations
- ADD COLUMN: city VARCHAR(25) DEFAULT 'Delhi' add kiya, sabki city Delhi set hui
- DROP COLUMN age kiya; RENAME TO se user ko insta user aur wapas user kiya
- CHANGE COLUMN se followers ko subs kiya; naam badalne par bhi data type (INT DEFAULT 0) dobara dena padta hai
- MODIFY subs INT DEFAULT 5 ke baad naye insert (id 7) mein subs by default 5 aaya
    - id 6 par duplicate entry error aaya, isliye 7 use kiya

### TRUNCATE vs DROP aur aage ka plan
- TRUNCATE data khaali karta hai par table rehti hai; DROP poori table hata deta hai
- Error 1701: post table ki foreign key user id ko reference kar rahi thi; post drop karke truncate chala
- Agla part: SQL ko Node backend se connect karna; pehle practice questions, jaise college database banana
