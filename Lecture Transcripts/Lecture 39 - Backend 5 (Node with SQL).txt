# Backend SQL with Faker Data

## Summary
### Flow Summary
Node.js backend ko mysql2 se delta\_app database se connect kiya, user table banayi aur Faker se 100 fake users bulk insert kiye; agla step Express routing (GET, PATCH, POST, DELETE).

### Faker se fake data
- Real-life databases ke liye manual data ki jagah @faker-js/faker package install kiya (npm init ke baad).
- getRandomUser function sirf chaar values return karta hai: id (UUID), username, email, password.
    - Har run par naya random data generate hota hai

### mysql2 se Node aur MySQL connection
- Flow: client server ko request bhejta hai, server database se baat karta hai; client kabhi direct database tak nahi jaata.
- mysql package ki jagah mysql2 use kiya, kyunki mysql mein authentication errors aa sakte hain.
- createConnection mein host localhost, user root, database delta\_app aur password diya; password pehle galat hone se access denied error aaya.
- connection.query(query, callback(err, result)) try/catch mein chalaya; kaam ke baad connection.end() se connection band karna zaroori.

### SQL commands chalane ke chaar tareeke
- Tareeke: MySQL Workbench, mysql2 package, CLI (mysql -u root -p), aur SQL files (source schema.sql).
- CLI se quit ya Ctrl D se exit hota hai; saare tareeke ek hi database par synced rehte hain.
- schema.sql se user table banayi: id varchar(50) primary key, username unique, email unique not null, password not null.
- Result ek array hota hai; result.length aur result[0] se individual objects nikalte hain; query ko variable q mein rakhna behtar.

### Placeholders aur bulk insert
- Placeholders (?) se dynamic values array ke roop mein connection.query ka doosra argument banti hain.
- Multiple users ke liye array of arrays aur single ? (VALUES ?) use kiya; 2 records ek saath insert hue.
- Loop se 100 Faker users data array mein push karke insert kiye: Records 100, duplicates 0, warnings 0.
    - UUID deprecated warning abhi ignore kiya

### Express routing ka plan
- GET /home: database mein users ki count dikhayega.
- GET /user: EJS page par id, email, username dikhayega; password sensitive hai isliye nahi dikhega.
- PATCH /user/:id: sirf username edit hoga, email aur password nahi.
- POST /user (naya user) aur DELETE /user/:id (password maangkar) homework rahenge; pehle teen class mein banenge.

### Agle Kadam
- (Students) Class ke saath GET /home, GET /user aur PATCH /user/:id routes implement karna
- (Students) Homework: POST /user se naya user add aur DELETE /user/:id password verify karke implement karna

# Express App User Management Demo

## Summary
### Flow Summary
Express + MySQL app mein teen routes bane: home (total 103 users count), /user (sabhi users ki table) aur password-check ke saath PATCH se username update. Homework: add user aur delete user routes.

### Express setup aur home route
- npm i express aur uuid install kiya; uuid homework mein naya user add karne ke liye chahiye hoga
    - Server app.listen se port 8080 par, nodemon index.js se run
- Home route (GET /) par SELECT count(\*) FROM user query: 103 users (100 faker se, 3 manually)
- res.send mein sirf number bhejne par Express use status code samajhta hai (deprecated warning)
- EJS install karke app.set view engine aur views path.join se set; home.ejs count aur "Join us today" button dikhata hai
    - app.use ki jagah app.set likhna tha, isi se error aaya tha

### Show users route (/user)
- SELECT \* FROM user se saare users laaye, result showusers.ejs ko users naam se pass kiya
- EJS for loop se table mein id, email, username dikhaye; table par 1 pixel solid black border
- connection.end ki zarurat nahi, response jaane par connection khud end ho jaata hai

### Edit aur update route
- Har row mein "edit username" button, GET /user/:id/edit par edit.ejs form kholta hai (id se user fetch)
    - Form mein existing username aur password input
- Form se PATCH request ke liye method-override (?\_method=PATCH) aur express.urlencoded use kiya
- PATCH /user/:id ke teen steps: id se user dhoondo, form password match karo, UPDATE query se username badlo
    - Galat password par "wrong password" response; success par res.redirect /user
- Test: pat74 ko Shraddha aur theo61 ko apnacollege\_delta kiya; changes server restart ke baad bhi persist
    - JS array ke changes ke ulat, database changes permanent hain

### Homework aur aage ka plan
- Dono homework ka solution GitHub par Delta project mein pushed hai; pehle khud try karna hai
- SQL ke basic commands tak hi cover hoga (joins, views, triggers nahi); aage focus MongoDB par, final project ke liye

### Agle Kadam
- (Students) POST /user route banao jo naya user database mein add kare (uuid ke saath)
- (Students) DELETE /user/:id route banao: sahi email aur password par user delete karke all users page par redirect
- (Students) Database mein row add/delete karke check karo ki home page ka count change hota hai
