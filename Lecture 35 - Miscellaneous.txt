# GET vs POST Requests

## Summary
### Flow Summary
GET aur POST requests par tutorial: GET ki limits (URL length, string data, data URL mein dikhna) aur POST ka body-based data bhejna, Express server ke saath demo kiya gaya.

### GET request ki limitations
- GET request response lene ke liye use hoti hai; extra data query strings mein jaata hai
- Har browser (Chrome, Safari, Edge) mein URL length ki limit hoti hai, isliye limited data hi bhej sakte hain
- Query string ka data hamesha string type ka hota hai aur URL mein dikhta hai, jo safe nahi hai
- Form demo mein username aur password (apna college, 1 2 3 4) URL mein saaf dikhe

### POST request ka use
- POST mein form data URL mein nahi, request body mein jaata hai
- POST database mein kuch create, write ya update karne ke liye; jaise Google Drive upload, jabki Google search GET hai
- POST ke saath JSON, XML, form URL encoded, plain text, HTML jaisa koi bhi data bhej sakte hain
- Ye convention hai, zaroori nahi; acha developer GET aur POST ko unke kaam ke liye hi use karta hai

### Express server setup aur testing
- miscellaneous folder mein frontend (index.html) aur backend subfolders banaye gaye
- Backend: npm init -y, npm i express, index.js mein port 8080 par server, nodemon index.js se start
- app.get aur app.post se /register route par standard get aur post response bheje, Hoppscotch se test kiya
- Form action mein pura http://localhost:8080/register likhna pada kyunki form file protocol use kar raha tha

### Request data access karna
- GET mein form data request.query se milta hai; user aur password destructure kiye
- Response mein "standard get response welcome apna college" wapas aaya
- POST body ko kaise access karein, ye agla topic hai

## Summary
### Flow Summary
Speaker 1 ne JavaScript OOP mein inheritance samjhaya: extends aur super keywords, Person/Student/Teacher aur Mammal/Dog/Cat examples, aur method overriding.

### Inheritance ka concept
- Child class parent (base) class ki saari properties aur methods inherit karti hai, jaise hum parents se aadatein lete hain
- Inheritance: already existing classes ke basis par nayi classes banane ka mechanism

### extends aur super keywords
- extends: child class ka naam, phir extends, phir parent class ka naam likhte hain (jaise Student extends Person)
- super constructor ke andar use hota hai aur parent class ke constructor ko call karta hai
- super(name, age) se name aur age parent mein initialize hote hain, this.name likhne ki zaroorat nahi

### Person, Student, Teacher demo
- console.log se order dikhaya: pehle student class constructor, phir person class constructor, phir marks initialize
- student1.talk() kaam karta hai jabki talk method sirf Person class mein hai
- Teacher Eve (age 32, subject English) mein name, age, subject aaye; talk prototype chain se mila

### Mammal, Dog, Cat example
- Mammal base class: constructor mein type = warm blooded, name lega, aur eat() method 'I am eating'
- Dog aur Cat dono Mammal extend karte hain, name super constructor ko pass karte hain
- Dog ka apna bark() method, Cat ka apna meow(); bark sirf Dog ke paas, eat dono ke paas
- Dog 'Tuffy' banakar name, type, eat aur bark sab access karke dikhaye

### Method overriding
- Dog class mein same naam ka eat() banaya to 'dog is eating' print hua, parent wala override ho gaya
- Child class mein same naam ka method ho to child ki implementation use hoti hai
